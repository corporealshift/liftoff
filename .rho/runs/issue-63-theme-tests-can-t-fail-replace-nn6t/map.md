## Facts checked outside the repo

- Kotlin's `assert` really is `-ea`-gated: the stdlib docs for `assert` say it "Throws an AssertionError if the value is false **and runtime assertions have been enabled on the JVM using the -ea JVM option**" (kotlinlang.org `kotlin/assert.html`). So the brief's claim is right; `check()`/explicit throw is unconditional.
- Whether AGP's unit-test task passes `-ea` is not settled here: AGP's 8.7.3 jar contains no reference to `enableAssertions`, so it inherits Gradle's `Test` default. The plan does not depend on the answer — the replacement makes the check unconditional either way.
